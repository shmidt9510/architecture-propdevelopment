Таблица первичной проверки для соотвествтия бизнес-требованиям

Главный вопрос почему проливаются данные между разными пользователями. Это должно сидеть как критическая задача для бизнеса, не только из соображений проверки безопасности

| Вопрос                                                                                                                                   | статус | описание |
| ---------------------------------------------------------------------------------------------------------------------------------------- | -------| ------------ |
| **I. Управление доступом**|       |              |
| Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам?                                       |нет|необходимо создать отдельный сервис авторизации для внутренних сотрудников|
| Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа?                                                        |частично|требует аудита|
| Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам?                                       |нет|требуется сервис мониторинга доступа до админок|
| Используются ли системы аутентификации пользователей для доступа к системам?                                                             |да||
| Созданы ли замкнутые контуры для подсистем, работающих с чувствительными данными?                                                        |да|требует аудита|
| Ограничен ли доступ к системам из внешних источников?                                                                                    |частично||
| Ведётся ли единый реестр учётных записей?                                                                                               |частично|требуется отдельный фронтенд сервис на объединение|
| Используются ли средства централизованного контроля доступа?|нет|в отдельный сервис логирования и авторизации|
| **II. Безопасность данных**                                                                                                                    |       |              |
| Разработана ли политика классификации данных, и актуализируется ли она в соответствии с действующим законодательством?                  |частично|В BI процессах явно не указано шифрование, как и в процессах для бухгалтеров|
| Реализованы ли механизмы управления ключами шифрования?|нет|требуется сервис управления ключами для доступа к смэв|
| Проводится ли регулярное резервное копирование данных? Хранятся ли резервные копии в защищённых хранилищах?|да||
| Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки и хранения для различных типов данных?|частично|требует аудита|
| Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности для маркировки данных?|неизвестно|требует аудита|
| Применяются ли средства или процессы анонимизации данных?|неизвестно|требует аудита для расширения BI|
| **III. Защита инфраструктуры**                                                                                                                 |       |              |
| Используется ли межсетевой экран для ограничения входящего и исходящего трафика?|частично|только для внешних пользователей|
| Реализована ли сегментация сети на логические зоны (DMZ, корпоративная сеть, гостевая сеть) для ограничения доступа к критическим ресурсам? |да|разделение кубер доступа|
| Используются ли IDS/IPS-системы для обнаружения и предотвращения сетевых атак?|да||
| **IV. Управление инцидентами**                                                                                                                 |       |              |
| Система управления инцедентами|неизвестно|требует аудита|
